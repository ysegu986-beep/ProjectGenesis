# Genesis 意思決定ログ

ここには、決めたことと、まだ決めていないことを残す。

理由を残すことで、あとから「なんでこうしたんだっけ」を減らす。

## 決定済み

### 2026-06-30: アークをエージェントリーダーに任命する

決定:

- Project Genesis のエージェントリーダーをアークにする。
- まずはユーザーとアークで作っていく。
- 第三者目線が必要なときだけ、新しいエージェントを呼ぶ。

理由:

Genesis は、まず手を動かしながら試作と改善を繰り返す段階にある。

視点を増やしすぎるより、ユーザーとアークで速く触れる形を作り、必要な場面だけ外部視点を入れる方が進みやすい。

### 2026-06-30: プロトタイプはCPU戦で試す

決定:

- 最初のブラウザ版は、あなた vs CPU の単独対戦にする。
- 2人対戦やオンライン対戦は後回しにする。

理由:

まず1人で何度も触って、マナ、召喚、攻撃、シールド、ターン進行の感触を確かめたい。

### 2026-06-30: 初回手札は体験優先で固定する

決定:

- 最初のテストでは、完全ランダム手札ではなく、基本行動が通る手札を用意する。

理由:

初回から何もできない手札になると、カードゲームの面白さではなく、操作不能感だけが残る。

ランダム性は、基本体験が動いてから検証する。

### 2026-06-30: 最初はデュエマに近い土台から始める

決定:

- マナ
- シールド
- ターン制
- クリーチャーによる攻撃
- 40枚デッキ

理由:

Genesis はデュエマから逃げるゲームではない。

まずは、好きだった体験が本当に今も面白いのかを確認する。

### 2026-06-30: 最初のプロトタイプは紙で遊べる形にする

決定:

- まず紙プロトタイプを作る。
- デジタル実装は、基本体験を確認してから進める。

理由:

ルールとカードの面白さは、最初に遊んで確認した方が早い。

### 2026-06-30: 初期カードはシンプルにする

決定:

- 複雑なタイミング
- 無限ループ
- サーチ多用
- 1枚で勝つカード

これらは初期カードプールでは避ける。

理由:

最初に確認したいのは、マナ、シールド、攻撃判断が面白いかどうか。

## 決定

### 先攻1ターン目にドローするか

先攻1ターン目はドローなしにする。

見ること:

- 先攻が強すぎるか。
- 後攻が手札で追いつけるか。
- ゲームテンポが遅すぎないか。

理由:

- 初期手札5枚とシールド5枚の40枚デッキで、先攻がすぐ6枚になると後攻との差が分かりにくい。
- 攻撃側が先に動ける分、最初の1ドローは後攻側の追いつき要素にした方が試合が締まりやすい。

### マナ支払いに文明一致を必要とするか

マナ支払いには文明一致を必要とする。

見ること:

- デッキ構築の意味が薄くならないか。
- 色事故が面白い緊張になるか、ただのストレスになるか。

理由:

- 5色コントロールなどを作る時、どの色をマナに置いたかが判断として重要になる。
- マナ自動支払いと手動選択を両方用意したため、色を意識する遊びを早めに確認できる。
