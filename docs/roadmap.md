# Genesis ロードマップ

## Phase 0: 土台作り

状態: 進行中

目的:

本格的な仕様書を書く前に、Project Genesis のブレない軸を決める。

文書:

- 設計原則
- やらないこと
- ルール設計思想

完了条件:

- Genesis が何を守りたいのか説明できる。
- Genesis が何をしないのか説明できる。
- ルール判断を安定した基準で見られる。

## Phase 1: ゲーム仕様

目的:

最初に遊べるルールセットを書く。

必要な文書:

- 基本のゲーム進行
- ターン構造
- ゾーン
- マナ、リソースシステム
- シールド、勝敗条件
- カードタイプ
- 文明、色のシステム
- タイミング、優先権ルール

完了条件:

- 書かれたルールだけで、2人が基本的な対戦を遊べる。
- 曖昧な状況を、なんとなく処理せず記録できる。

## Phase 2: プロトタイプカード

目的:

テスト用の小さなカードプールを作る。

目標:

- スターターデッキ 2つ
- 各40枚、または意図を持って決めた別サイズ
- 最初はシンプルな効果中心
- すべてのカードに存在する理由がある

完了条件:

- 何度か遊んでも、毎回違う判断が生まれる。
- 枠を埋めるためだけのカードがない。

## Phase 3: エンジンプロトタイプ

目的:

基本ルールを処理できるデジタルプロトタイプを作る。

最初の範囲:

- ローカル対戦のみ
- 手動デッキ選択
- 基本のターン進行
- マナ置き
- 召喚
- 攻撃
- シールドブレイク
- 勝敗判定

完了条件:

- ローカルで1試合を最後まで遊べる。
- ルールやカード挙動をデバッグできるログが残る。

## Phase 4: UIプロトタイプ

目的:

UI がプレイヤーの代わりに考えず、読みやすく遊びやすい状態を作る。

UI が助けること:

- できる行動の表示
- 現在フェーズの表示
- カードテキストの読みやすさ
- 盤面の分かりやすさ
- 履歴、ログの確認

UI が避けること:

- おすすめ行動
- リーサル表示
- 最適プレイの誘導
